# Cycle 3 计划 — 买家旅程打磨 + 后台订单处理（2026-10-14）

## 评估结论（c3_eval.py / c3_admin.py，手机 390 + 桌面 1440）
1. 商品页数量改为 2 后，页面价格和手机吸底栏仍显示单价 ¥48.00，没有“合计”——买家不知道要付多少（最高价值）。
2. 多规格商品卡只显示首个规格价（如 Spotify 首规格 ¥15，另一规格 ¥158；Netflix ¥39/¥109），没有“起”价，且排序按首规格价。
3. 404/错误页是英文 “Page Not Found”，没有页头页脚、没有返回链接。
4. 搜索面板：只有首页有推荐商品，商品页打开搜索只显示提示文字；搜不到时只有一句话，没有推荐兜底。
5. 结算页错误态：标题下同时显示“正在确认订单信息...”和“无法继续支付”，且错误时没有任何按钮。
6. prefers-reduced-motion：首页 hero `animate-fade-up`、页头位移、图片缩放仍在动。
7. 后台订单详情（手机）：信息单列竖排、标题居中，长单需要滚很久；发货对话框看不到商品/数量/联系方式/买家备注，要来回切详情。
8. 后台仪表盘（手机）：5 张指标卡单列，每张 134px，图表被推到第二屏以下。

## 方案比较与取舍
- 合计显示：A 改服务端返回合计（锁定，否）；B 前端 `price × qty` 仅用于展示，有优惠预览时用服务端 finalAmount（选 B，提交仍按服务端算价，行为不变）。
- “起”价：A 改 `server/catalog/public.ts` 返回 minPrice（server 目录，避免）；B 在 `pages/index/+data.server.ts` 里额外只读查询 ACTIVE 规格的最小价与数量（选 B，server/ 无改动；页面数据加两个可选字段）。
- 非首页搜索推荐：A 每个页面都查目录（贵）；B 只在商品页 data 里复用 `getPublicCatalog`（最常见的搜索入口）（选 B）。
- 错误页：用 StoreShell + i18n 文案 + 返回首页/查询订单；后台路径不受影响（后台有自己的布局与守卫）。
- 后台：只改模板/样式（订单页非支付页，但仍不改脚本逻辑）。

## 不做
- 不改支付页脚本、服务端路由、订单逻辑；不加购物车（单商品直购是现有业务模型，加购物车属于方向级变化）。
